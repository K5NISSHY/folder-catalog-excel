# Folder Catalog Excel — 要件定義書

作成日: 2026-11-24 / 作成: Strata アシスタント（ユーザーの依頼に基づく） / 状態: **承認済み（2026-11-24・CSVオプション追加の改訂を反映）**

## 0. 要求定義

### 0.1 背景・課題

共有フォルダやプロジェクトフォルダの中身を把握したい場面は多い（棚卸し、引き継ぎ、保存期限の確認、不要ファイルの洗い出し、容量調査）。Windows には `tree` コマンドがあるが、出力は**文字のツリー図**であり、次の理由で実務ではそのまま使えない。

| 観点 | `tree`（コマンドプロンプト） | このツール（Excel出力） |
| --- | --- | --- |
| 出力の形 | 文字のツリー図（`└──` などの罫線文字）。コピーすると崩れることがある | 1行=1ファイルの表。ソート・フィルタ・数式が使える |
| ファイルサイズ | 出ない（`tree` は名前のみ） | 出る（KB・合計・フォルダ別集計） |
| 更新日時・作成日時 | 出ない | 出る（新しい順・古い順に並べ替え可能） |
| 拡張子・種類 | 分からない | 拡張子別の件数・合計サイズを集計 |
| 階層の深さ | 罫線の数でしか分からない | 階層レベル・フォルダ名が別列（フィルタで「3階層目だけ」が可能） |
| 大容量フォルダ | 画面に収まらず、スクロールで全体像が掴めない | 件数・合計サイズが冒頭に表示され、集計シートで把握できる |
| 後処理 | テキストを表に直す作業が発生（コピペ→列の分離→整形） | 完成した表がそのまま出てくる |
| 文字化け | コードページ（`chcp`）や罫線文字で崩れることがある | Excelに直接書くため影響ない |

`tree` は「ざっと見る」用途、Excel出力は「**並べ替えて判断する・人に渡す**」用途、という違いを記事で示す。

### 0.2 解決したいこと

- フォルダを選ぶ → 実行するだけで、**中身の目録がExcelで出てくる**
- 出てきた表を**そのままフィルタ・ソート・集計に使える**（「1年更新されていないファイル」「100MB超」「.tmp だけ」など）
- 実行前に「何件・どのくらいの量になるか」が分かり、**間違えて巨大フォルダを走らせても止める判断ができる**
- 失敗（アクセスできないフォルダ、長すぎるパス）で**落ちずに、失敗した箇所だけ一覧に残る**

### 0.3 成功の目安（受け入れの目線）

| 観点 | 目安 |
| --- | --- |
| 時間 | 1万ファイル規模のフォルダを数分で目録化できる。実行中は進捗が見え、フリーズしない |
| 正確性 | 収集件数とExcelの行数が一致する。アクセス不可のフォルダは行数から消えず「エラー一覧」に記録される |
| 使いやすさ | ダブルクリックで起動、フォルダ選択→実行→Excelが開く。既存のExcelファイルは絶対に上書きしない |
| 比較できる | 同じフォルダで `tree /F` と並べても劣らない情報量（サイズ・日時・集計）がExcel側にある |

## 1. 要件定義

### 1.1 目的

指定フォルダ配下を再帰的に走査し、**ファイル一覧・フォルダ集計・拡張子集計・エラー一覧**を1つのExcelワークブックに出力する単一画面のWindowsツール。

### 1.2 機能要件

| ID | 要件 | 優先度 | 達成状況 |
| --- | --- | --- | --- |
| FR-1 | 対象フォルダをダイアログで選択できる（手入力も可） | Must | 達成 |
| FR-2 | 選択したフォルダ配下を再帰的に走査し、ファイルとフォルダを収集する | Must | 達成 |
| FR-3 | 実行前に**事前プレビュー**（想定件数・合計サイズ・最深階層・対象フォルダの絶対パス）を表示し、実行はプレビュー後にできる | Must | 達成 |
| FR-4 | Excelシート「一覧」を出力する。列は No / 相対パス / 階層レベル / 直下のフォルダ / ファイル名 / 拡張子 / サイズ(KB) / 更新日時 / 作成日時 | Must | 達成 |
| FR-5 | Excelシート「フォルダ集計」を出力する（フォルダ単位のファイル数・合計サイズ・最深階層） | Must | 達成 |
| FR-6 | Excelシート「拡張子集計」を出力する（拡張子単位の件数・合計サイズ・最大ファイル） | Must | 達成 |
| FR-7 | 見出し行に**フィルタ**を付け、先頭行を固定し、列幅を調整する（開いてすぐ使える書式） | Must | 達成 |
| FR-8 | 出力ファイル名は `<フォルダ名>_目録_<YYYYMMDD_HHMM>.xlsx`。同名ファイルが存在する場合は**自動で連番を付けて上書きしない** | Must | 達成 |
| FR-9 | 除外オプション: 隠しファイル／システムファイル、特定フォルダ（`.git`, `node_modules`, `$RECYCLE.BIN`, `System Volume Information`, `desktop.ini` 等）を既定で除外し、チェックで解除できる | Must | 達成 |
| FR-10 | アクセス拒否・長すぎるパスなどの失敗は**クラッシュさせず**、シート「エラー一覧」にパスと理由を記録する | Must | 達成 |
| FR-11 | 走査は別スレッドで行い、GUIはフリーズしない。進捗（処理件数・現在のフォルダ）と**中止ボタン**を備える | Must | 達成 |
| FR-12 | 出力先フォルダを選択できる（既定は対象フォルダの親） | Should | 達成 |
| FR-13 | 件数上限（安全装置）を指定できる（既定 200,000 件。超過時は警告して停止） | Should | 達成 |
| FR-14 | 完了時に生成ファイルのパスと件数を表示し、Excelを起動するか選べる | Should | 達成 |
| FR-15 | 前回実行の設定（除外オプション・上限）を覚えておく | Could | 達成（同じ起動中に限定。設定ファイルへの永続化はしない） |
| FR-16 | **CSVでも書き出せる**（チェックボックスのオプション。既定はオフ）。ONにすると同じ目録を **UTF-8（BOM付き）** のCSVでも出力し、Excelと同じベース名にする | Must | 達成 |

### 1.4 設計方針

- 走査は `os.scandir` を自前で再帰（`os.walk` でも可）し、`PermissionError` などをその場で拾ってエラー一覧へ積む
- 収集データは**行のタプルを順にためる**軽量な形にし、Excel書き出しは openpyxl の `write_only=True` でストリーム的に書く
- 件数が多い場合はプレビューで警告（例: 5万件超は「時間がかかります」）
- 画面は既存ツール（pdf-split-unified）と同じ思想: **上に入力、下に「プレビュー」→「実行」**、実行前に全件（ここでは要約）が見える

### 1.5 対象外（スコープ外）

- ファイルの**移動・削除・リネーム・圧縮**（読み取り専用の目録のみ）
- 重複ファイルのハッシュ判定（別ツール C2 の領域）
- JSON などの **Excel・CSV 以外**の出力形式【改訂: 承認時にユーザーから「CSVはチェックボックスのオプションで入れたい」との指定があり、CSVを FR-16 としてスコープ内へ移動した】
- 実行履歴のデータベース化、常駐、スケジューラ連携
- 権限の昇格（管理者としてしか読めないフォルダの強制走査）
- 実行ファイル（exe）化、インストールインストーラー

## 4. 実行手順

### 4.1 アプリの起動

```
起動.bat            ← ダブルクリック
```

`起動.bat` は同じフォルダに `.venv` があれば `.venv\Scripts\pythonw.exe` を使い、
無ければ `py -3` に落ちる。**ライブラリのインストール手順は要求しない**（openpyxl の入った環境を使う）。
`pythonw.exe` を使うので黒いコンソール窓は残らない。

**注意**: `起動.bat` は **Shift-JIS (CP932)** で保存している。UTF-8 に変換すると cmd.exe が行頭を食い違って
コメント行をコマンドとして実行しようとし、起動しなくなる（実測で再現・修正済み）。

### 4.2 テスト・検証（開発系）

```
.venv\Scripts\python.exe -m unittest -v test_folder_catalog_excel
```

標準の `unittest` を使う（pytest は使わない）。終了コード 0 が PASS。

### 4.3 サンプル資料による実行検証

```
.venv\Scripts\python.exe tools\make_samples.py         ← samples/ を作る（既存ファイルは上書きしない）
.venv\Scripts\python.exe tools\run_sample_catalog.py   ← 実行走査＋Excel/CSV 生成＋機械判定
.venv\Scripts\python.exe tools\tree_compare.py         ← tree /F 形式のツリー図と突き合わせ
```

`tools/run_sample_catalog.py` は 10 項目の機械判定を出し、全項目 PASS のときだけ終了コード 0 を返す。
`tools/tree_compare.py` は `samples/検証結果/tree_F.txt`（`tree /F` と同じ形式のテキスト・UTF-8 BOM 付き）を作り、
ファイル数・フォルダ数が Excel 側と一致するかを判定する。

### 4.4 配布用最小パッケージ

| 必須 | ファイル |
| --- | --- |
| 必須 | `folder_catalog_excel.py`, `scan_core.py`, `catalog_writer.py`, `起動.bat` |

### 5.7 大規模実測（NFR-3）

一時フォルダに 100 フォルダ × 1,000 ファイル = **100,000 ファイル**のツリーを作り、実測した。

| 工程 | 実測 |
| --- | --- |
| 走査（`scan_core.scan`） | 100,000 ファイル / 100 フォルダ / **1.28 秒** / ワークセット **83.3 MB** / エラー 0 |
| Excel 書き出し（`write_only`） | 3,885,304 バイト / **9.55 秒** / ピーク **84.0 MB** |
| CSV 書き出し（2 種類） | **0.21 秒** |
| 生成 xlsx の読み戻し | 一覧 `A1:I100001`（見出し + 100,000 行）/ 8.63 秒 |

→ 10 万件規模でもメモリは 100 MB 未満で安定。1 万件規模なら走査は 1 秒未満（0.3.0 の「数分」目安を大きく満たす）。

## 6. 既知の問題・留意点

| 項目 | 内容 |
| --- | --- |
| `起動.bat` の文字コード | **Shift-JIS (CP932) で保存する**。UTF-8 に変えると cmd.exe が改行位置を誤認して壊れる（5.9 参照） |
| KB の丸め | 1 行ずつ四捨五入しているため、「一覧」の KB 合計はサマリーの合計（バイト基準）と数 KB ずれることがある（実測 43,528 vs 43,530）。拡張子集計は拡張子単位で丸めるためさらに違う値になる（実測 43,531） |
| 日時の型 | Excel には `YYYY-MM-DD HH:MM:SS` の**文字列**で書く。20 万セルのスタイル指定を避けるためで、並べ替え・フィルタはそのまま効くが、`=` などの日付数式には使えない |
| 出力フォルダを対象に含めると | 出力先を対象フォルダ（またはその配下）にすると、生成した Excel/CSV が次の走査に混ざる。GUI は同じ起動中はそれを避けるが、別実行では除外名に出力フォルダ名を足す必要がある（`tools/run_sample_catalog.py` はその方法で除外している） |
| リンク・ジャンクション | 一覧には出るが**中は走査しない**（ループ防止）。中のファイルが必要ならリンク先を対象にして実行する |
| 長いパス | 260 文字超は拡張パス表記（`\\?\` / `\\?\UNC\`）で 1 回だけ再試行する。それでも失敗したものはエラー一覧に出る |
| 件数上限 | 既定 200,000 件。到達すると途中で停止し、サマリーとエラー一覧に記録される（その部分だけ目録が不完全） |
| 設定の記憶 | 同じ起動中のみ。設定ファイルには書かない（FR-15 の合意どおり） |
| `samples/` の git 管理 | **ダミーのサンプルツリー本体（87 ファイル / 42.5 MB）は git に含まない**（`tools/make_samples.py` で再現できるため）。**検証の出力（`samples/検証結果/` の xlsx・csv・tree_F.txt）は含める**（読者が実行しなくても結果を確認できるため）。【改訂: 記事・README で検証結果を参照するため、`samples/` 一式を除外する方針から変更】 |
