# 実装依頼: folder-catalog-excel（フォルダ目録Excel作成ツール）

## 0. 前提

- プロジェクトフォルダ: `folder-catalog-excel`（このフォルダ内だけを変更・作成すること。他のフォルダに手を出さない）
- **承認済みの要件定義書が `docs/PROJECT_DOCUMENT.md` にある。まず全文を読むこと。** 以下はその要約であり、矛盾があれば `docs/PROJECT_DOCUMENT.md` を正とする
- 実行環境: Python 3.15.2、プロジェクト内の `.venv`（`.venv\Scripts\python.exe`）。openpyxl 3.1.5 と Tkinter はインストール済み
- **追加ライブラリは禁止。`pip install` も禁止**（標準ライブラリと openpyxl のみで実装すること）
- ドキュメント・コメント・README・UI文言は**日本語**。コード内の識別子は英語
- **ドキュメントやコードコメントに絶対パスを書かない**（リポジトリ相対で書く）

## 1. 作るもの

指定フォルダ配下を再帰的に走査し、**ファイル一覧・フォルダ集計・拡張子集計・エラー一覧**を1つのExcelワークブックに出力する単一画面の Windows ツール（Tkinter）。`tree` コマンドのテキスト出力では実務に使えないので、Excelで使える目録を出すのが目的。

## 2. 機能要件（Must をすべて満たす）

- FR-1 対象フォルダをダイアログで選択できる（手入力も可）
- FR-2 選択したフォルダ配下を再帰的に走査し、ファイルとフォルダを収集する
- FR-3 実行前に**事前プレビュー**（想定件数・合計サイズ・最深階層・対象フォルダの絶対パス）を表示し、実行はプレビュー後にできる
- FR-4 シート「一覧」: 1行=1ファイル。列は `No / 相対パス / 階層レベル / 直下のフォルダ / ファイル名 / 拡張子 / サイズ(KB) / 更新日時 / 作成日時`
- FR-5 シート「フォルダ集計」: 1行=1フォルダ（ファイル数・合計サイズ・最深階層）
- FR-6 シート「拡張子集計」: 1行=1拡張子（件数・合計サイズ・最大ファイルサイズ）
- FR-7 見出し行に**フィルタ**、**先頭行固定**、列幅調整を施す（開いてすぐ使える書式）
- FR-8 出力ファイル名は `<フォルダ名>_目録_<YYYYMMDD_HHMM>.xlsx`。同名ファイルが存在する場合は**自動で連番を付けて上書きしない**（例: `..._目録_20261124_1200 (2).xlsx`）
- FR-9 除外オプション: 隠しファイル／システムファイル、および特定フォルダ・ファイル（`.git`, `node_modules`, `$RECYCLE.BIN`, `System Volume Information`, `desktop.ini`, `Thumbs.db`）を**既定で除外**し、チェックで解除できる
- FR-10 アクセス拒否・長すぎるパスなどの失敗は**クラッシュさせず**、シート「エラー一覧」にパスと理由を記録する
- FR-11 走査は別スレッドで行い、GUIはフリーズしない。進捗（処理件数・現在のフォルダ）と**中止ボタン**を備える
- FR-12 出力先フォルダを選択できる（既定は対象フォルダの親）
- FR-13 件数上限（安全装置）を指定できる（既定 200,000 件。超過時は警告して停止し、その旨をサマリーに残す）
- FR-14 完了時に生成ファイルのパスと件数を表示し、Excelを起動するか選べる
- FR-16 **CSV書き出しのチェックボックス（既定はオフ）**。ONにすると同じ目録を **UTF-8（BOM付き）** のCSVでも出す。CSVはシート「一覧」と「フォルダ集計」の2種類、Excelと同じベース名（`..._目録_20261124_1200_一覧.csv` のように接尾で区別）

## 3. 非機能要件

- NFR-1 標準ライブラリ＋openpyxl のみ
- NFR-2 GUIは Tkinter（ttk）。exe化はしない。`起動.bat` で起動できるようにする（pdf-split-unified と同じ書き方。venvがあればそれを使い、無ければ `py -3` で起動。ライブラリ導入手順をbatの中で要求しない）
- NFR-3 大容量でも破綻しない。openpyxl の `write_only=True` を使い、10万件規模でメモリが爆発しない実装にする
- NFR-4 日本語ファイル名・日本語フォルダ名・スペース入り・長めのパスで正しく動く
- NFR-5 **既存ファイルを上書きしない。ファイルの移動・削除・リネームを一切しない**（読み取り専用）
- NFR-6 ネットワークドライブのパスも対象にできる
- NFR-7 単体テストを `test_folder_catalog_excel.py` に用意し、機械判定で PASS すること（標準の `unittest` を使う。pytest は導入しない）
- NFR-8 検証用のサンプルフォルダを自動生成するスクリプトを用意する（個人情報・実データは一切使わない）

## 4. ファイル構成（この名前のまま作る）

| ファイル | 役割 |
| --- | --- |
| `scan_core.py` | 走査と収集（GUI非依存）。`os.scandir` を自前で再帰し、`PermissionError` などをその場で拾ってエラー一覧へ積む。進捗コールバックと中止フラグを受け取る |
| `catalog_writer.py` | Excel書き出し（GUI非依存）とCSV書き出し（FR-16） |
| `folder_catalog_excel.py` | Tkinter GUI。上に入力、下に「プレビュー」→「実行」 |
| `test_folder_catalog_excel.py` | 単体テスト（一時フォルダに作った見本ツリーに対する収集ロジック、除外判定、出力ファイル名の連番規則、CSVエンコーディング） |
| `tools/make_samples.py` | 検証用サンプルフォルダ生成。`samples/` 配下に**日本語名・多階層（4階層以上）・各種拡張子（.xlsx/.docx/.pdf/.png/.txt/.csv/.zip）・サイズ差・更新日の差**のあるダミーツリーを作る。ファイル数は 60〜120 程度 |
| `tools/run_sample_catalog.py` | サンプルフォルダに対して実行走査＋Excel/CSV生成をスクリプトから実行し、**機械判定**（収集件数とExcel行数の一致、シート5枚の有無、フィルタ設定、合計サイズの一致、エラー一覧の存在、CSVのBOM、上書き防止の連番）を出力する |
| `tools/tree_compare.py` | 記事用の比較材料。同じサンプルフォルダに対する `tree /F` のテキスト出力（サブプロセスではなく、Python側でツリー図文字列を生成してもよい）と、Excel側の集計値（件数・合計サイズ・フォルダ数）を突き合わせて表示する |
| `README.md` | 日本語。できること／必要な環境／使い方／Excelのシート構成／tree との違い／注意点。検証結果の具体的な数値は書かない（docs に書く） |

## 5. 作ってはいけないもの

- ページ範囲指定のような追加機能、exe化、D&D対応、設定ファイルの外部保存（FR-15 は「同じ実行中」の記憶まで。ファイルへの永続化はしない）
- 追加ライブラリ、`pip install`、ネットワークアクセス
- 対象フォルダ内のファイルに対する書き込み・移動・削除

## 6. 完了時の報告形式

以下の**実測値**を数値で報告すること（概算・見込みは書かない）:

1. 作成したファイル一覧と行数
2. `test_folder_catalog_excel.py` の実行結果（テスト数と PASS/FAIL、終了コード）
3. `tools/make_samples.py` が作ったサンプルのファイル数・フォルダ数・合計サイズ
4. `tools/run_sample_catalog.py` の機械判定結果（各項目の PASS/FAIL と TOTAL）
5. `tools/tree_compare.py` の出力（tree側とExcel側の突き合わせ結果）
6. GUIを起動できたか（ウィンドウサイズの実測）
